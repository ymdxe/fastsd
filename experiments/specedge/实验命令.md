如果 PowerShell 当前执行策略拦截脚本，仅为本次进程运行：

路径为 CPU `127.0.0.1:29736` → 本机 `127.0.0.1:19736` → GPU `127.0.0.1:19736`。三端均使用现有 SSH 身份，不向服务器复制私钥。脚本只管理自己启动的 SSH 进程，退出时关闭它们。实际测试期间，本机需保持唤醒和联网；这种连接用于功能测试，其延迟不能解释为 IB 直连性能。

## 2. 在 gpunode2 启动 Target

先确认当前分配给你的物理 GPU 编号。下面的 `1` 是物理卡号，可改为实际分配的编号；启动器会拒绝已有计算进程的卡，不会停止其他实验。

```bash
bash /home/hdd3/zhangh/workspace/fastsd/specedge-cpu-gpu-20261026/launch.sh check
bash /home/hdd3/zhangh/workspace/fastsd/specedge-cpu-gpu-20261026/launch.sh server specedge_smoke_01 --gpu 1
```

保持 GPU 窗口打开。必须等到日志出现以下提示，再执行 CPU 命令：

```text
TARGET READY: specedge_smoke_01; clients=1; start the CPU client(s) now.
```

如果想在 GPU 的另一个终端查看加载状态：

```bash
bash /home/hdd3/zhangh/workspace/fastsd/specedge-cpu-gpu-20261026/launch.sh status specedge_smoke_01
```

`specedge-ready.json` 表示模型及 CUDA Graph 已完成初始化；只有 gRPC listening 提示不足以证明 Target 就绪。失败会保存 `specedge-failed.json`。

## 3. 在 cpunode1 启动一个 Draft，完成四条请求

```bash
bash /home/zhangh/workspace/fastsd/specedge-cpu-gpu-20261026/launch.sh check
bash /home/zhangh/workspace/fastsd/specedge-cpu-gpu-20261026/launch.sh client specedge_smoke_01 --requests 4 --max-tokens 32 --threads 8 --gamma 4
```

CPU 日志会依次显示模型加载、Sync、预热和 `COMPLETED 1/4` 至 `COMPLETED 4/4`。完成后自动写入 `summary.json`；应有 `all_requests_completed: true`、`requests: 4`。EOS 提前结束时输出可少于 32 token。

```bash
cat /home/zhangh/workspace/fastsd/exp/specedge_manual_20261026/specedge_smoke_01/node1-client0/summary.json
cat /home/zhangh/workspace/fastsd/exp/specedge_manual_20261026/specedge_smoke_01/node1-client0/exit-status.json
```

CPU 完成后，在 GPU 原服务窗口按 Ctrl+C 结束本轮 Target，再关闭本机连接脚本。每轮使用新 RUN_ID，例如 `specedge_smoke_02`；旧目录和日志存在时启动会拒绝覆盖。

## 结果和边界

- GPU：`/home/hdd3/zhangh/workspace/fastsd/exp/specedge_manual_20261026/<RUN_ID>/server/`
- CPU：`/home/zhangh/workspace/fastsd/exp/specedge_manual_20261026/<RUN_ID>/<node>-client<idx>/`
- 终端输出：同一结果根目录下 `<RUN_ID>.<server或client>.<hostname>.console.log`。
- 请求记录：CPU 的 `requests.jsonl` 保存输出 token、文本、完成延迟、TTFT、应用层通信字节和 RPC 数；`summary.json` 保存完成数量与平均延迟。
- 复现资料：`launch.json`、`commands.txt`、`config.json`/`specedge-config.json`、`runtime.json`、`gpu.json`、`exit-status.json`；包内 `manifest.json` 固定同步文件内容。

这些命令用于验证该 CPU 适配实现能否完成推理。四条短请求与 SSH 转发不足以支持性能结论；本入口没有做与 AR 的逐 token 一致性比对。检查结果见同目录 `同步与预检记录.md`。
